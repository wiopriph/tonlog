# Публикация Tonlog в Cloudflare Workers + D1

Приложение подготовлено для **Cloudflare Workers**. Email хранятся в D1, в таблице `waitlist`. Автоматическая отправка писем не подключена.

## 1. Установить зависимости и войти в Cloudflare

В терминале, в папке проекта (Node.js 24):

```sh
npm ci
npx wrangler login
```

Откроется браузер для входа в ваш аккаунт Cloudflare. Токены и пароли в код добавлять не нужно.

## 2. Создать базу D1

В панели Cloudflare откройте **Storage & databases → D1 SQL database → Create Database**. Назовите базу **tonlog-waitlist**, затем скопируйте ее **Database ID**.

Альтернатива через терминал:

```sh
npm run db:create
```

Если база уже создана в панели, повторно создавать ее командой не нужно.

В `wrangler.jsonc` замените `00000000-0000-0000-0000-000000000000` на Database ID. Сохраните остальные поля:

```json
{
  "binding": "DB",
  "database_name": "tonlog-waitlist",
  "database_id": "ваш-database-id",
  "migrations_dir": "migrations"
}
```

`DB` — имя подключения, которое использует сервер. Database ID не является секретом. Если вы выбрали другое название базы, измените `database_name` и название в командах `db:*` в `package.json`.

Настройки подключения нужно сохранять в `wrangler.jsonc`: этот файл используется при каждом деплое. Подключение базы только через панель может быть перезаписано следующей публикацией из кода.

## 3. Создать таблицу в настоящей базе

```sh
npm run db:migrate:remote
```

Команда применит `migrations/0001_create_waitlist.sql` в Cloudflare. Подтвердите применение, если Wrangler спросит. Повторный запуск не удаляет заявки: примененные миграции учитываются автоматически.

Можно проверить таблицу в панели: **D1 → tonlog-waitlist → Tables → waitlist**. Если выбранный интерфейс не показывает Tables, откройте Console и выполните `SELECT * FROM waitlist;`.

## 4. Собрать и опубликовать

```sh
npm run build
npm run deploy
```

Wrangler опубликует Worker `tonlog` и покажет адрес `https://tonlog.<ваш-поддомен>.workers.dev`. Свой домен можно подключить в настройках опубликованного Worker.

Перед публикацией проверьте имя `tonlog` в `wrangler.jsonc`: если в вашем аккаунте уже есть Worker с таким именем, деплой обновит его. Для отдельного проекта задайте другое имя.

## 5. Проверить форму

Откройте опубликованный сайт, отправьте свой email и проверьте появление записи в D1. Повторная отправка того же адреса должна оставлять одну запись. Email приводятся к нижнему регистру, сохраняются вместе с датой в UTC и источником `landing`.

Если форма сообщает об ошибке, проверьте:

- В `wrangler.jsonc` указан настоящий Database ID.
- В опубликованном Worker есть D1 binding **DB**, указывающий на нужную базу.
- Миграция была применена с `--remote`, а не только локально.
- После исправления конфигурации выполнены сборка и деплой.

## Автодеплой из GitHub / GitLab

После добавления репозитория в **Workers & Pages** выберите создание **Worker**, подключите репозиторий и задайте:

| Поле | Значение |
| --- | --- |
| Корневая папка | Корень этого проекта |
| Build command | `npm run build` |
| Deploy command | `npm run deploy` |
| Node.js | `24` (при необходимости переменная сборки `NODE_VERSION=24`) |

Команды `npm run db:migrate:remote` достаточно выполнить из своего терминала перед первым деплоем и затем при добавлении новых миграций. Автодеплой не применяет миграции сам. Изменения Database ID должны попасть в репозиторий до сборки.

Не используйте статический экспорт `nuxt generate`: форме нужен серверный маршрут `/api/waitlist`.

## Локальная разработка

Для локальной D1 не нужен вход в аккаунт и настоящий Database ID:

```sh
npm run db:migrate:local
npm run dev
```

Nuxt подключает локальный эмулятор Cloudflare. Данные сохраняются в `.wrangler/state/v3`, исключенной из Git. Локальная база и настоящая D1 в Cloudflare независимы.

Для проверки именно production-сборки в Workers runtime:

```sh
npm run build
npm run preview
```

Локальный preview обычно доступен на `http://127.0.0.1:8787`. Миграцию `db:migrate:local` нужно выполнить заранее.

Старые заявки из `.data/waitlist` автоматически в D1 не переносятся. Перед удалением старой папки сохраните или импортируйте нужные записи. Пароли, `.dev.vars`, локальная база и `.env` исключены из Git.
